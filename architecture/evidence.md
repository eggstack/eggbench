# Evidence architecture

`eggbench-core` owns the portable `.eggb` directory contract: a versioned manifest, typed run/trial IDs, confined artifact paths, bounded metadata, artifact sensitivity labels, SHA-256 digests, streaming staging/finalization, and a read-only inspector. The manifest is authoritative; directory naming conventions do not define what evidence exists.

Writers create a hidden sibling staging directory, stream and hash artifacts in bounded chunks, flush artifact files, validate primary plan/resolved-plan/environment references and trial references, verify staged bytes, then write `manifest.json` last. Final publication uses a same-directory atomic rename and refuses an existing destination. On Linux the no-replace rename primitive is used; other platforms use a create-new finalization lock and same-directory rename. No cross-filesystem copy fallback is attempted. Windows does not expose portable directory syncing through `std`; artifact and manifest file contents are flushed, while directory-entry durability is provided by the OS/filesystem.

Published bundles expose no writer API. Inspectors reject staging directories, unsupported schemas, unmanifested files, missing or corrupt artifacts, unsafe relative paths, and symlinks. On Unix, artifact files are opened relative to directory handles with no-follow flags so replaced path components cannot redirect file reads outside the bundle. Verification is explicit and read-only.

Manifest v1 is read through an explicit legacy DTO and preserves its original `RunStatus`. Its `inconclusive` value is ambiguous between “no comparison” and an inconclusive comparison; the reader exposes that legacy marker and does not infer a verdict. New writes use manifest v2, which stores `execution_status` independently from optional `comparison_verdict`; a verdict requires a comparison artifact, and a comparison artifact requires a verdict. A completed run without comparison therefore has `execution_status: completed` and no verdict. V1 unknown top-level additive fields remain readable; nested fields and variants stay strict. V2 retains additive top-level compatibility, while fields changing interpretation require a version bump. Both versions require subject identity, one plan, resolved plan, and versioned environment fingerprint. Environment fields declare comparison-critical, warning-only, or informational classification. The manifest stores relative references, driver inventory, optional trial/comparison/report references, artifact byte sizes and SHA-256 values, plus the count/byte bounds applied by the writer. It does not embed artifact contents.
