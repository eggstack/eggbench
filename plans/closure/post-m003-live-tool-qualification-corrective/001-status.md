## 5. Exact mismatch (C002 scope, recorded — not patched)

Against `eggprobe v0.1.1` (`53ea53d`) source
`crates/eggprobe-core/src/domain/{plan,target}.rs` and CLI batch parsing:

Plan generation (`build_probe_plan`, `handshake_eggprobe` in
`crates/eggbench-drivers/src/external/eggprobe.rs`):

- P1 — `probes` are emitted as plain strings (`["dns","tcp","http"]`). The
  real `ProbeSpec` is `#[serde(tag = "kind")]`: `{"kind":"dns"}`,
  `{"kind":"tcp","port":N}`, `{"kind":"http","url":"..."}`. Tcp/Http carry
  required port/url fields.
- P2 — `execution` is emitted as
  `{"repetitions":1,"retries":0,"deadline_ms":N}`. The real `ExecutionPolicy`
  is `{"deadline":<integer microseconds>,"repetitions":1,"retries":0}`.
  (Reference: eggprobe's own CLI tests use
  `{"deadline": 1_000_000, "repetitions": 1, "retries": 0}`.)
- P3 — `target` is emitted as `{host,port,tls,http_url}`. The real
  `TargetSpec` accepts only `{host, optional port}` under
  `deny_unknown_fields`; `tls`/`http_url` are rejected.
- P4 — the handshake empty-probe plan and the single-DNS retry plan carry
  the same three defects.

Report parsing (`parse_probe_report`, `classify_probe_exit`, handshake
`status == "pass"` check):

- P5 — entries are read from `family`; the real `ProbeResult` serializes the
  family as `kind` (`Dns/Tcp/Tls/Http` as snake_case strings).
- P6 — status vocabulary is `ok` / `failed` / `unsupported` / `cancelled`
  (snake_case `ReportStatus`/`ProbeStatus`), not `pass` / `fail`. Consequences:
  the handshake `parsed.status != "pass"` gate and the exit-0 mapping would
  reject/misclassify even a byte-correct plan.
- Compatible, no change needed: process exit classes 0/1/2/3/130
  (`ExitCode::Success/Negative/Invalid/Internal/Interrupted`), schema-`0.3`
  string form, `tool.name == "eggprobe"` with non-empty version, direct route
  summary, `execution_id`/`target` presence.

EggReplay side: no defect found. Real `validate`/`replay --output json`
matches the M003a adapter exactly (envelope 1, session 1-or-2 accepted,
RegressionReport 2, `finding_count` consistency, exit-0 replay semantics for
both match and mismatch). Combined-run EggReplay evidence is still deferred
to C002 only because the Eggprobe handshake gates startup first.

A sibling defect was not found; both siblings behaved per their own sources.
No Eggprobe schema-0.4 adoption is required: the fix stays on the qualified
0.3 contract.

## 7. Why previous verification missed this

M003a/M003b closure testing used hand-written fixture/report JSON shaped by
the adapter author's reading of the sibling contract, plus (for Eggprobe) the
audited schema-0.3 *string* without executing the real binary's typed
`ProbePlan` deserializer. The mock reports used `family`/`pass` vocabulary
that the real `ProbeResult`/`ReportStatus` types never emitted, and the
generated plan was never fed to `eggprobe run -`. C001's live execution is
the first check that crossed the real process seam — which is exactly the gap
it was created to close.

## 8. Residual risks and notes

- The deterministic origin used for fixture generation is a raw-socket
  loopback server emitting zero timestamp headers. A stock HTTP server that
  emits `Date` (e.g. Python `http.server`) records a varying header and
  replays with exactly one `response.headers.date` finding. The committed
  `origin_raw.py` documents this; C002 reuses it.
- `eggreplay record` readiness parsing (`recording on ...` stderr line)
  exists only in the qualification harness, never in production, per plan
  section 4.
- Fixture aggregate digests via Eggbench's M003a identity code were not
  captured because no Eggbench preflight got past the Eggprobe handshake.
